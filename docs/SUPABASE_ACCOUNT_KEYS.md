# 계좌 조회 전 Supabase 최신 키 자동 수신 · 1.14.0

Supabase Secrets에 보관한 기관 키를 계좌 조회 직전에 Android 네이티브 코드가 HTTPS로 받아 사용한다. 키는 JS 화면/브리지 응답·로그·저장소·APK에 포함하지 않는다. 기관 잔고는 여전히 휴대폰에서 직접 조회하므로 등록 Wi-Fi와 기관에 허용한 공인 IPv4가 필요하다.

## 이용 순서

1. asset-hub → Edge Functions → Secrets에 키움은 KIWOOM_APP_KEY / KIWOOM_APP_SECRET, 업비트는 UPBIT_ACCESS_KEY / UPBIT_SECRET_KEY를 등록한다. Publishable key는 변경하지 않는다. 업비트는 자산조회 권한만 부여한다.
2. 1.14.0으로 업데이트하고 기존 본인 계정으로 앱을 한 번 연다. 이미 연결한 기관은 로그인 인증 후 자동 키 수신 권한을 이전한다.
3. 처음 연결하는 기관은 설정 → Wi-Fi 등록 → 기관별 ‘계좌 자동 조회 연결’에서 최초 한 번 자산 교체와 기기 자동 키 수신에 동의한다. 이후 키 가져오기 버튼을 매번 누를 필요가 없다.
4. 계좌 조회 조건이 맞으면 Supabase 최신 키 수신 → 기관 잔고 조회 → 자산 동기화 → 위젯 반영 순서로 진행한다. Secrets에서 키를 교체하면 다음 실제 계좌 조회부터 새 키를 받는다. 이미 오늘 조회했다면 키 교체로 하루 한 번 제한을 초기화하지 않는다.

키 수신 실패 시 저장된 이전 키로 대신 조회하지 않는다. 잔고가 이미 수신되어 업로드 대기 중이면 키·기관 조회를 반복하지 않고 잔고만 재전송한다. 기존 기기 키는 업데이트 호환을 위해 암호화 보관하지만 새로운 실제 잔고 조회에서는 최신 키를 사용한다. 로그아웃 시 기기 보안 자료를 삭제하고 등록 기기 폐기를 시도한다. 연결 해제는 해당 기관의 서버 자동 키 수신 권한도 폐기하며, Secrets 자체는 유지한다.

## 조회와 갱신 시점 (한국 시간)

| 구분 | 조건과 주기 |
|---|---|
| 계좌 잔고 | 기관별·기기별 날짜당 정상 잔고 1회. WorkManager 약 15분 간격 실행 기회에 등록 Wi-Fi의 SSID와 공인 IPv4가 일치하고 아직 오늘 성공하지 않은 경우 조회. 자정 이후 다음 기회 또는 나중에 등록 Wi-Fi에 연결된 첫 기회에 실행 |
| 실패한 계좌 조회 | 이전 시도에서 30분 이상 지난 뒤 조건이 맞을 때 재시도. 계좌를 다시 읽을 때마다 최신 키를 다시 수신 |
| 업로드 재시도 | 정상 수신한 잔고를 보관해 재전송. 계좌/키 재조회 없음 |
| 위젯 일일 시세 | 매일 자정 00:00 이후 네트워크가 있고 Android 실행이 허용될 때 1회 성공 갱신. 실패하면 30분 지수 백오프로 최대 2회 추가 시도 |
| 계좌 동기화 후 위젯 | 같은 계좌 작업에서 새 수량/원금을 가져와 공개 시세와 함께 즉시 갱신 시도. 미완료 시 약 15분 이후 작업 기회에 재시도하며 계좌는 다시 조회하지 않음 |
| 앱이 열려 있을 때 | 앱 진입·다시 활성화·당겨서 새로고침·설정한 1/5/15분 간격에 시세/자산을 갱신해 위젯에도 반영. 기본 1분이며 Yahoo 주식·ETF 응답은 5분 캐시, 환율은 일별 기준. 계좌 하루 한 번 제한은 그대로 적용 |

Android 절전/강제 종료/통신 상태로 정각과 정확한 간격은 보장하지 않는다. 로그인·위젯 등록·권한·시세 입력이 필요하며 위젯 전체 삭제 시 일일 시세 작업은 중단한다. 계좌 작업은 별도이므로 등록 Wi-Fi·연결 기관이 있는 동안 계속 유지한다. 등록 Wi-Fi에 연결되지 않은 날도 일일 위젯 공개 시세는 다른 인터넷으로 갱신 가능하다. 위치 좌표는 수집하지 않는다.

## 서버 권한

- ACCOUNT_KEY_OWNER_USER_ID로 명시한 본인 Auth 사용자만 권한을 등록한다. 사용자 metadata나 첫 요청 사용자로 소유자를 정하지 않는다.
- credentials: 사용자 JWT(auth.getUser) + 기기 ID/토큰 해시/만료/동일 소유자/직접 조회 scope를 확인한다. autoRefresh=true이면 해당 기관의 자동 수신 권한을 부여한다.
- background-credentials: 유효한 기기 인증과 credential_providers의 해당 기관 권한, 현재 지정된 키 소유자가 모두 일치해야 한다. 공개 anon JWT만으로 접근할 수 없다. 예전 읽기/스냅샷 토큰은 기본 권한이 빈 배열이다.
- JWT로 기기를 등록할 때 이미 연결된 기관만 자동 이전한다. 새 기관은 위 동의를 통해 연결한다. 기기 토큰/URL/공개 JWT는 Android Keystore 암호화·백업 제외 파일에만 보관하며 사용자 JWT/refresh token을 백그라운드용으로 저장하지 않는다.
- 기기 권한의 만료는 등록/로그인 갱신 기준 365일이며 앱을 새로 실행해 로그인 등록을 갱신한다. 토큰 만료·삭제·권한 해제 시 키 수신을 거부한다.
- credential_providers와 원자적 권한 변경 함수는 service_role만 접근한다. RLS와 앱 역할 접근 금지는 유지한다. 키 값은 일반 테이블에 저장하지 않는다. 응답은 no-store이고 네이티브 HTTP는 캐시/리다이렉트를 사용하지 않는다.

실제 기관 키 값과 개인 계좌를 개발 도구로 조회하지 않았으므로 실제 잔고·Wi-Fi/절전 실행·설치는 휴대폰에서 확인해야 한다.
