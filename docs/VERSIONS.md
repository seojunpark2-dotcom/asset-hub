# APK 버전 규칙 · 2026-10-11

사용자의 최신 요청에 따라 `앞.중간.마지막` 숫자를 변경 내용에 맞춰 올립니다. 마지막 숫자만 올리던 이전 규칙은 폐기했습니다.

| 변경 종류 | 올리는 숫자 | 예시 |
|---|---|---|
| 기존 사용 방식이나 데이터·연동과 호환되지 않는 큰 변경 | 앞 (major), 나머지는 0 | 1.2.1 → 2.0.0 |
| 기존 기능과 호환되는 새 기능 추가 | 중간 (minor), 마지막은 0 | 1.2.1 → 1.3.0 |
| 오류 수정, 기능 추가 없는 UI·문서·설정 정리 | 마지막 (patch) | 1.2.1 → 1.2.2 |

여러 종류의 변경이 함께 있으면 가장 높은 종류를 적용합니다. 단순한 화면 디자인 변경이나 개발 도구 변경만으로 major를 올리지 않습니다. 내부 수정·테스트·빌드 재시도는 별도 버전으로 세지 않습니다.

현재 작업 브랜치는 connect이며 버전은 1.12.0입니다. 복수 Wi-Fi 등록·수정·삭제 기능 추가에 minor를 적용했습니다. main은 1.8.0을 유지합니다. 이미 배포한 APK 파일과 태그는 당시 실제 버전을 유지합니다. 과거 1.0.3 표기의 예외도 보존하되, 성공 배포 이력에서 가장 높은 정상 버전을 기준으로 계산하여 버전이 후퇴하지 않도록 검사합니다.

## 다음 수정 시
1. 성공적으로 업로드·검증된 APK를 `release-history.json`의 releases에 기록하고 plannedRelease를 제거합니다.
2. 변경 종류를 판단하여 `npm run version:bump -- patch`, `npm run version:bump -- minor`, `npm run version:bump -- major` 중 하나를 실행합니다. 종류 생략은 허용하지 않습니다.
3. 앱/패키지/잠금 파일과 Android versionCode를 함께 갱신하고 이력에 plannedRelease를 저장합니다. 같은 종류로 반복 실행하면 같은 결과를 유지합니다.
4. `npm run version:check`와 GitHub APK 빌드를 실행합니다. 기존 버전 재사용, 메타데이터 불일치, 계획과 다른 버전 증가를 빌드 전에 차단합니다.

Android versionCode는 변경 종류와 관계없이 마지막 성공 배포보다 1 증가합니다. 기존 패키지와 서명을 유지해 설치 앱을 업데이트할 수 있습니다.
