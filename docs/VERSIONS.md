# APK 버전 규칙 · 2026-10-11

사용자 요청 및 확인에 따라 APK 배포마다 마지막 숫자만 1씩 증가시킵니다. `1.0.3 → 1.0.4 → 1.0.5` 순서이며, 중간 숫자를 올리지 않습니다. 한 배포를 준비하는 내부 수정·테스트·빌드 재시도는 별도의 배포 횟수로 세지 않습니다.

| 새 배포 순번 | 기존 APK의 실제 표기 | Android versionCode | 내용 |
|---|---|---:|---|
| 1.0.0 | 1.0.0 | 2 | 최초 APK |
| 1.0.1 | 1.1.0 | 3 | API 만료일 표시·알림 |
| 1.0.2 | 1.2.0 | 4 | 달력 선택·단일 알림·자동 날짜 변경 |
| 1.0.3 | 1.0.3 | 5 | 이전 배포를 포함한 버전 표기 정리 |

과거 APK 파일과 Git 태그는 당시 실제 버전을 유지합니다. 위 대응표로 과거 수정 횟수를 포함합니다. 새 표기 1.0.3은 기존 표기 1.2.0보다 숫자로 작지만 Android 업데이트 판단에 쓰는 versionCode는 4 → 5로 증가하므로 기존 앱에 업데이트할 수 있습니다.

## 다음 수정 시
1. 성공적으로 업로드된 마지막 APK를 `release-history.json`에 기록합니다. 아직 배포하지 못한 빌드 재시도는 기록하지 않습니다.
2. `npm run version:bump`를 실행합니다. app.json/package.json/package-lock.json을 맞추고 Android versionCode도 1 증가시킵니다. 같은 배포 준비 중 반복 실행해도 추가로 증가하지 않습니다.
3. 수정·검사 후 `npm run version:check`와 GitHub APK 빌드를 실행합니다. 빌드에서는 이 규칙을 자동 검사합니다.

현재 1.0.3 APK 생성 시 이력에는 마지막 성공 배포 1.0.2까지 포함합니다. 1.0.3의 업로드가 성공하면 다음 작업에서 이력에 추가한 뒤 1.0.4로 올립니다.
