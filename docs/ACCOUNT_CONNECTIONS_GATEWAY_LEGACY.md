# 키움증권·업비트 자동 연동 (1.9.0)

## 현재 준비 상태

앱·DB·계좌 API 중계 코드와 설치 구성을 제공합니다. 실제 고정 IP 서버와 개인 API 키는 아직 없으므로 실제 계좌 연결은 설정 후 가능합니다. 준비 전 앱은 `연결 준비 필요`로 표시하며 가짜 잔고나 연결 완료 상태를 만들지 않습니다. 이번 작업은 connect 브랜치에서만 진행합니다.

## 구조

앱/Supabase 인증 → portfolio-accounts Edge Function → 본인 소유 고정 IP 서버 → 키움/업비트 공식 API → 검증된 전체 잔고를 DB 트랜잭션으로 반영합니다. Supabase Edge Functions 자체에는 고정 송신 IP가 없어 계좌 API를 직접 호출하지 않습니다.

- 계좌 동기화는 보유종목·수량·매입원금을 가져옵니다. 주식·ETF 시세는 Yahoo, 코인은 Upbit, 환율은 Frankfurter를 계속 사용합니다.
- 키움 실전 REST 키에 연결된 **한 계좌의 국내 현금 주식·ETF**와 업비트 키에 연결된 **한 포켓의 KRW 기준 코인**을 지원합니다. 예수금, 신용·대주, ETN/ELW, 키움 해외주식, 미래에셋은 이번 자동 연동 범위가 아닙니다. 지원 불가 잔고나 불완전한 페이지는 전체 동기화를 실패 처리하여 기존 자산을 유지합니다.
- 업비트 수량은 `balance + locked`입니다. 현금 KRW는 코인 목록에 넣지 않습니다. 증정 등 매입원금 0인 코인은 금액·손익을 표시하고 수익률은 `—`로 표시합니다.
- 첫 연결 시 해당 기관의 지원 범위에 해당하는 수동 자산을 실제 잔고로 교체한다는 동의를 받습니다. 미래에셋과 키움 해외주식 등 다른 자산은 유지합니다. 기존 수동 자산이 실제 계좌에 없으면 교체 시 제거됩니다.
- 연결 이후 신규 매수·수량 변경·전량 매도를 자동 반영합니다. 자동 자산은 직접 편집·삭제할 수 없습니다. 연결 해제하면 마지막 잔고가 수동 자산으로 남고 다시 편집할 수 있습니다.
- 현재 전체 최대 49개 자산을 지원합니다. 초과 시 DB 트랜잭션을 취소하고 기존 자산을 유지합니다. 수수료·세금·배당과 매입원금 집계 기준 차이 때문에 증권사 화면과 평가손익이 다를 수 있습니다.

## 1. 고정 IP 서버 준비

본인이 관리하는 서버에 **고정 공인 IPv4**, HTTPS에 사용할 도메인, Docker Engine와 Compose가 필요합니다. 서버·고정 IP·도메인 요금은 제공업체에 따라 다릅니다. 이 작업에서 유료 서버를 생성하거나 결제를 진행하지 않았습니다.

1. 서버의 고정 공인 IPv4를 확보합니다. DNS A 레코드를 연결용 도메인에서 해당 IP로 설정합니다.
2. 서버 방화벽의 80/443 포트를 HTTPS용으로 허용합니다. 8080 포트는 외부에 열지 않습니다.
3. 이 비공개 저장소의 connect 브랜치를 서버에 내려받습니다. `server/.env.example`을 `server/.env`로 복사하고 파일 권한을 소유자만 읽도록 설정합니다(`chmod 600 .env`).
4. 서버 Node 24 또는 임시 Node 컨테이너에서 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`로 공용 인증 비밀값을 하나 생성해 `.env`의 `GATEWAY_SHARED_SECRET`에 넣습니다. 실제 값은 채팅·이슈·GitHub 파일에 올리지 않습니다.
5. 앱 설정 → 계좌 자동 연동에 표시되는 내 사용자 ID를 `ACCOUNT_OWNER_USER_ID`에 넣습니다. 이 서버는 이 한 사용자만 허용합니다.
6. `ACCOUNT_DOMAIN`에 연결용 도메인만 넣습니다(예: `accounts.example.com`).

## 2. 키움 REST API 키 발급

1. https://openapi.kiwoom.com/ → 본인 계정 로그인 → REST API 서비스 신청을 진행합니다. 기존 Windows OCX OpenAPI+ 키와 다릅니다.
2. 실전 계좌 App Key 관리에서 서버의 **고정 공인 IP**를 허용 목록에 등록합니다. 휴대폰 사설 IP나 도메인을 넣지 않습니다.
3. 가져올 국내 주식·ETF 계좌를 연결하고 실전용 App Key와 Secret Key를 발급합니다.
4. 서버 `.env`의 `KIWOOM_APP_KEY`, `KIWOOM_APP_SECRET`에 각각 넣습니다. 키움 아이디 비밀번호·계좌 비밀번호를 이 앱에 입력하지 않습니다.
5. 중계 서버가 `/oauth2/token`으로 접근 토큰을 발급하고 만료 전에 다시 발급합니다. 이는 앱키 자체의 사용기간·서비스 이용 갱신을 대행한다는 의미가 아닙니다. 실제 키의 만료·계좌 이용조건은 키움 관리 화면에서 확인해야 합니다.

## 3. 업비트 API 키 발급

1. 업비트 **PC 웹** 로그인 → 마이페이지 → Open API 관리로 이동합니다.
2. **자산조회 권한만** 선택합니다. 주문·출금·입금 권한은 이 앱에 필요하지 않습니다.
3. 동일한 서버 고정 공인 IP를 허용 목록에 등록하고 본인 추가 인증을 완료합니다.
4. Access Key와 최초 한 번 표시되는 Secret Key를 서버 `.env`의 `UPBIT_ACCESS_KEY`, `UPBIT_SECRET_KEY`에 넣습니다. 발급한 키가 조회할 포켓을 확인합니다.
5. API 키 자체의 만료는 앱에서 임의로 연장할 수 없습니다. 만료·폐기·IP 변경 시 본인이 재발급/수정하고 서버를 다시 시작해야 합니다. 요청별 JWT는 서버가 자동 생성합니다.

한 기관만 설정하면 그 기관부터 연결할 수 있습니다.

## 4. 서버 실행과 Supabase 연결

`server` 디렉터리에서 `docker compose up -d --build`를 실행합니다. Caddy가 도메인의 HTTPS 인증서를 발급·갱신하고 외부 요청을 내부 gateway로 전달합니다. 이 서버는 계좌 조회·토큰 발급 경로만 구현하며 주문·출금 경로는 없습니다.

Supabase asset-hub → Edge Functions → Secrets에 다음 **서버 설정**을 추가합니다. Publishable key 입력란이 아닙니다.

| 이름 | 값 |
|---|---|
| ACCOUNT_GATEWAY_URL | `https://연결용도메인/` (루트 주소, 끝 슬래시 포함) |
| ACCOUNT_GATEWAY_SECRET | 서버 GATEWAY_SHARED_SECRET과 같은 값 |

기관의 API 키는 Supabase에 중복 저장하지 않습니다. 서버 `.env` 파일·Compose의 환경변수 출력·컨테이너 상세 정보를 공유하지 않습니다. 서버 설정을 바꿨다면 `docker compose up -d --force-recreate gateway`로 재시작합니다.

## 5. 앱에서 연결

1. 최신 APK로 업데이트하고 로그인합니다.
2. 설정 → 계좌 자동 연동 → `연결 상태 다시 확인`을 누릅니다.
3. 해당 기관이 `연결 가능`이 되면 `계좌 연결 및 자산 가져오기`를 누르고 수동 자산 교체를 확인합니다.
4. 실제 잔고 조회·전체 페이지 검증·DB 저장이 모두 성공해야 `연결됨`으로 바뀝니다. 자산 탭에서 자동 등록된 종목을 확인합니다.
5. 이후 앱 시세 갱신 시 계좌 잔고도 확인합니다(정상 잔고 5분 재사용, 연속 요청 30초 제한). 즉시 확인하려면 `지금 잔고 동기화`를 누릅니다.

## 위젯과 보안

한국 시간 매일 자정 이후 WorkManager가 **계좌 동기화 → 최신 보유자산 수신 → 시세 조회 → 위젯 갱신**을 실행합니다. 앱 화면은 열지 않습니다. 절전·인터넷 문제·강제 종료 시 지연·중단될 수 있습니다.

Edge Function의 기본 JWT 검증을 유지합니다. 위젯은 공개 anon JWT로 기본 검증을 통과한 뒤 별도 기기 토큰과 만료일을 추가 검증받습니다. 공개 JWT만으로는 포트폴리오를 조회할 수 없으며, 사용자 작업은 별도로 auth.getUser를 검증합니다.

계좌 API 비밀키와 Supabase 관리 키는 APK에 포함하지 않습니다. 위젯에는 본인 포트폴리오 조회·동기화만 허용하는 별도 무작위 기기 토큰을 사용합니다. 서버에는 토큰 해시만 저장하고 휴대폰에는 Android Keystore AES-GCM으로 암호화해 백업 제외 영역에 보관합니다. 기기 토큰은 1년 유효하며 앱을 열면 다시 등록해 유효기간을 갱신합니다. 장기간 앱을 전혀 열지 않아 만료되면 앱을 한 번 열어야 합니다.

로그아웃하면 기기 토큰을 삭제하고 가능한 경우 서버 등록도 해제합니다. 오프라인 로그아웃처럼 서버 해제가 불가능했던 토큰은 서버 만료일까지 남을 수 있지만 휴대폰의 토큰 파일은 삭제합니다. 기관 연결 해제는 서버에서 동기화를 중단하고, 다른 사용자의 계좌·비밀키를 조회할 수 있는 권한을 제공하지 않습니다.

## 검증 한계

구현은 공급자 응답을 재현한 테스트와 DB 소유권/트랜잭션 테스트로 검증합니다. 실제 계좌 잔고, 키움 키의 계좌 연결, 업비트 권한/IP, 서버 HTTPS·송신 IP, 실기기 Keystore·자정 수신은 서버와 키를 설정한 뒤 확인해야 합니다. 아직 실제 계좌 연결이 완료됐다고 표시하지 않습니다.
